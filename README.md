# Still Launcher

Still is an independent, privacy-first Android launcher prototype built with Kotlin and Jetpack Compose. Its visual direction is quiet typography, simple spacing, and customization without a dashboard-template aesthetic.

## Current status

This is a working project foundation, not a claim that every feature in the original product brief is complete. See [FEATURE_STATUS.md](FEATURE_STATUS.md) for implemented and partial areas.

### Requirements
- Android Studio with Android SDK 36 installed
- JDK 17 or newer (Java 21 is fine)
- Gradle wrapper generated by Android Studio, or a local Gradle 8.11+ installation compatible with Android Gradle Plugin 8.10.1

## Build
Open the project root in Android Studio and allow Gradle sync. If a wrapper has not been generated, use Android Studio's Gradle tooling or run `gradle wrapper` with a compatible local Gradle installation. Then:

```bash
./gradlew test
./gradlew assembleDebug
```

APK output: `app/build/outputs/apk/debug/app-debug.apk`

## Install and set as default
1. Build and install the debug APK from Android Studio, or use `adb install app/build/outputs/apk/debug/app-debug.apk`.
2. Open Still Launcher.
3. Open Customize → Set as default home.
4. Select Still Launcher in Android's Home app chooser/settings.
5. Press the device Home gesture/button to use it.

OEM settings names vary. You can switch back to your previous launcher from Android Settings → Apps → Default apps → Home app.

## Privacy
The manifest intentionally does not request `INTERNET`, location, contacts, calendar, notification access, usage access, or broad package visibility. Installed launchable activities are queried through a launcher intent. Core launch, local search, preferences, and palette metadata work offline. Third-party widgets execute as their provider apps and may have their own data practices.

Launcher preferences use AndroidX DataStore. The export currently writes a versioned JSON preference profile into the app-specific external files directory. That export is not a secure portable backup and does not include widget provider state. Import validation and document-picker UI are not implemented yet.

## Widgets
The widget integration uses `AppWidgetHost` and `AppWidgetManager`, including system bind/configuration flows. Android/OEM restrictions may vary. This initial UI binds the first installed widget provider rather than presenting a complete provider-picker/preview catalog; treat widget discovery and placement as partial.
